Custom DNS Query with Optional NSID Retrieval

Purpose

This PowerShell script performs DNS lookups against a specified DNS server for a given hostname and record type, with an optional feature to retrieve the Name Server Identifier (NSID) using EDNS(0) over UDP and TCP.

1. Parameter Handling

Powershell

param (

    [Parameter(Mandatory = $true)]

    [string]$Hostname,

    [Parameter(Mandatory = $true)]

    [string]$RecordType,

    [Parameter(Mandatory = $true)]

    [string]$DnsServer,

    [switch]$NSID

)

  • $Hostname — Target domain name.
  • $RecordType — DNS record type (e.g., A, AAAA, MX).
  • $DnsServer — IP or hostname of the DNS server to query.
  • $NSID — Optional switch to trigger NSID retrieval.

2. Core Helper Functions

2.1 Skip-DnsName

  • Purpose: Parses DNS message format to skip over a domain name (handles compression pointers).
  • Logic:
    • Reads label lengths until a zero byte (end of name) or a compression pointer (0xC0) is found.
    • Returns the new offset in the byte array.

2.2 Build-NsidQueryPacket

  • Purpose: Constructs a raw DNS query packet with an EDNS(0) OPT record requesting NSID.
  • Key Steps:
    • Generates a random transaction ID.
    • Sets standard query flags (0x0100).
    • Encodes the query name into DNS label format.
    • Appends QTYPE=1 (A record) and QCLASS=1 (IN).
    • Adds an OPT pseudo-record with:
      • Type = 41 (OPT)
      • UDP payload size = 4096
      • Option code = 3 (NSID)
      • Option length = 0 (request only)

2.3 Parse-NsidFromResponse

  • Purpose: Extracts NSID data from a DNS response.
  • Logic:
    • Reads answer, authority, and additional record counts.
    • Skips over answer and authority sections.
    • Iterates through additional records to find OPT record (type 41).
    • Searches for option code 3 (NSID) and returns its ASCII string.

3. NSID Retrieval Functions

3.1 Get-NSID-UDP

  • Sends the NSID query packet over UDP.
  • Sets a 3-second receive timeout.
  • Returns parsed NSID if found, otherwise $null.

3.2 Get-NSID-TCP

  • Sends the NSID query packet over TCP (with 2-byte length prefix).
  • Reads the full response.
  • Returns parsed NSID if found, otherwise $null.

3.3 Get-NSID

  • Tries UDP first, then TCP if no NSID is found.
  • Returns a descriptive string with the result.

4. Main Execution Flow

  1. Informational Output:
    • Displays DNS server and query target.
  2. DNS Query:
    • Uses Resolve-DnsName with the specified server and record type.
    • Formats results into a table showing:
      • Name
      • Type
      • TTL
      • IPAddress
      • NameHost
  3. Error Handling:
    • Catches and displays any exceptions from Resolve-DnsName.
  4. Optional NSID Retrieval:
    • If -NSID is specified, calls Get-NSID and displays the result.
  5. Completion Message:
    • Prints "Query complete." in green.

5. Error Handling & Edge Cases

  • Try/Catch blocks around:
    • Resolve-DnsName
    • UDP and TCP NSID retrieval
  • Timeouts:
    • UDP receive timeout set to 3000 ms.
  • Fallback:
    • If UDP fails, retries over TCP.
  • Graceful Failure:
    • Returns descriptive messages if NSID is not found.

6. Output Behavior

  • Color-coded messages:
    • Yellow for warnings/retries.
    • Cyan for section headers.
    • Green for success.
    • Red for errors.
  • Formatted tables for DNS answers.
  • Plain text for NSID results.

7. Features

  • Supports both UDP and TCP for NSID retrieval.
  • Handles DNS name compression in parsing.
  • Modular function design for maintainability.
  • Works with any DNS server (not just system default).
  • Provides clear, user-friendly output.

 

What is NSID?

  • NSID is an optional EDNS(0) feature (RFC 5001) that allows a DNS server to return an identifier string in its response.
  • It’s often used for debugging, load balancing verification, or identifying which physical server answered a query.

 

1. Background

  • NSID (Name Server Identifier) is defined in RFC 5001.
  • It’s an EDNS(0) option (Option Code = 3) that lets a DNS server return an identifier string in its response.
  • This is not returned in normal DNS queries — you must explicitly request it by adding an OPT pseudo-record to the query.

2. How the Script Requests NSID

2.1 Building the Query Packet

Function: Build-NsidQueryPacket

  • Creates a raw DNS query in binary form:
    1. Transaction ID — random 16-bit number.
    2. Flags — 0x0100 (standard query, recursion desired).
    3. Question Count — 1.
    4. Answer/Authority/Additional Counts — Additional Count = 1 (because we’re adding an OPT record).
    5. Question Section — Encodes $QueryName into DNS label format, followed by:
      • QTYPE = 1 (A record — the actual record type here doesn’t matter for NSID retrieval).
      • QCLASS = 1 (IN — Internet).
    6. Additional Section — Adds an OPT pseudo-record:
      • NAME = 0 (root)
      • TYPE = 41 (OPT)
      • UDP payload size = 4096
      • Extended RCODE & EDNS version = 0
      • Z field = 0
      • RDLEN = 4 (length of option data)
      • Option Code = 3 (NSID)
      • Option Length = 0 (request only, no data sent)

This packet is manually constructed as a byte array — bypassing PowerShell’s built-in DNS cmdlets — because Resolve-DnsName doesn’t expose EDNS(0) options.

3. Sending the Query

3.1 UDP Attempt

Function: Get-NSID-UDP

  • Creates a System.Net.Sockets.UdpClient.
  • Sets a 3-second receive timeout.
  • Sends the raw packet to $Server on port 53.
  • Waits for a response.
  • Passes the raw response bytes to Parse-NsidFromResponse.

3.2 TCP Fallback

Function: Get-NSID-TCP

  • If UDP fails or returns no NSID, retries over TCP.
  • Uses System.Net.Sockets.TcpClient.
  • Prepends a 2-byte length prefix (required for DNS over TCP).
  • Sends the packet, reads the length-prefixed response.
  • Passes the raw response bytes to Parse-NsidFromResponse.

4. Parsing the Response

Function: Parse-NsidFromResponse

  1. Read Header Counts:
    • ANCOUNT (answers)
    • NSCOUNT (authority records)
    • ARCOUNT (additional records)
  2. Skip Question Section:
    • Uses Skip-DnsName to move past the encoded domain name.
    • Skips QTYPE and QCLASS (4 bytes).
  3. Skip Answer & Authority Sections:
    • Loops through each record, skipping over names, fixed fields, and RDATA.
  4. Process Additional Section:
    • For each additional record:
      • Skip the name.
      • Read TYPE — if it’s 41 (OPT), this is the EDNS(0) record.
      • Read RDLEN (length of option data).
      • Inside the option data:
        • Read Option Code and Option Length.
        • If Option Code = 3 (NSID), extract the next Option Length bytes.
        • Convert those bytes to an ASCII string — this is the NSID.

5. Control Flow

Function: Get-NSID

  • Builds the NSID query packet.
  • Calls Get-NSID-UDP.
  • If UDP returns $null, prints a warning and calls Get-NSID-TCP.
  • Returns:
    • "NSID: <value>" if found.
    • "No NSID option found..." if not.

6. Why This Works

  • EDNS(0) allows adding extra metadata to DNS queries.
  • The OPT record with Option Code 3 is the standardized way to request NSID.
  • The server, if configured to support NSID, will return it in the Additional Section of the DNS response.
  • The script manually parses the binary DNS packet to extract this value — something PowerShell’s built-in DNS cmdlets cannot do.

7. Key Technical Points

  • Manual packet crafting is required because standard DNS libraries don’t expose NSID.
  • UDP first, TCP fallback ensures compatibility with servers that truncate large responses.
  • Binary parsing is done manually to handle DNS name compression and EDNS(0) option structures.
  • Option Code 3 is the trigger for NSID retrieval.
